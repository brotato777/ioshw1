【使用者需求（原文摘錄）】

  地獄模式尚未設計完成，先不考慮

  iOS 作業 1 猜拳接躲遊戲 — 開發規格書

  0. 遊戲名稱：猜猜拳

  1. 遊戲概述
  一句話：拳型物件不斷落下，玩家控制底部角色「接住打得贏的、閃開打不贏
  的」，而且玩家自己的拳型會定時輪替，逼你不斷重新判讀場面。
  勝負條件：生命歸零 → 遊戲結束，結算分數與最高分。

  2. 核心玩法
  關係            玩家該做    做對      做錯
  我方打得贏它    接住        得分      漏接 → 扣血
  它打得贏我      閃開        安全      碰到 → 扣血
  同拳型（平手）  忽略        無事      無事

  3. 操作方式：手指拖曳，按住畫面任意處左右滑動。

  4. 玩家拳型輪替
  每隔一段時間自動輪替。換拳前約 2 秒，角色的拳在「目前拳型 ↔ 下一個
  拳型」之間交替閃爍作為預告。

  5. 勝負判定 + 資料格式
  不要用一堆 if-else 寫死勝負關係。用資料表：每種拳型只宣告「我打得贏
  誰」，清單外一律算輸，同名算平手。
  判定就是一句話：「A 打贏 B ⟺ B 在 A 的打贏清單裡」。

  6. 生命 / 計分 / 結算
  生命依難度 5 / 3 / 1 / 1 顆。無敵幀 0.8 秒並閃爍。
  計分：接對 +100，存活每秒 +5。最高分分難度各存一筆。

  7. 難度設定
  難度  拳種       剋制圖  血量  掉落速度  生成間隔  換拳間隔  道具
  簡單  RPS (3)    顯示    5     慢        ~1.5s     ~12s      無
  普通  RPS (3)    顯示    3     中        ~1.1s     ~9s       有
  困難  RPSLS (5)  顯示    1     中快      ~1.0s     ~7s       有
  地獄  20+        不顯示  1     中        ~1.1s     ~8s       有
  隨時間遞增：每存活 30 秒 → 掉落速度 ×1.06、生成間隔 ×0.94，各設上限
  （速度最多初始 2.5 倍、生成間隔最短 0.5s）。

  8. 道具系統
  道具不是獨立物件，而是「塗」在原本的落下拳型物件上。碰到接盤 = 同時
  結算拳型勝負 + 觸發道具效果。道具永不直接扣血。同一時間只保留一個效
  果，吃到新的會覆蓋舊的。
  道具清單：亂流、勝負相反、貪婪、智慧、天黑請閉眼。

  9. 地獄模式 RPSplus20+（設計原則、戰報字幕）

  10. 畫面流程：標題 / 遊戲中（含暫停）/ 結束。
  我想在遊戲中畫面頂端放一個頭，表示正在跟玩家對決出拳的人，不同難度
  的人長得不一樣。玩家這邊也有一個頭，得分或扣分會有表情反應。

  11. 生成公平性規則（避免「無法閃的死」）
  不要同時在同一落點生成「唯一能接的物件」和「該閃的物件」。
  別讓長時間沒有任何可接物件。
  負面道具不要卡在必經路徑上跟扣血情境重疊。

【驗證與修掉的問題】

  1. 崩潰（SIGTRAP，索引越界）
     resolveCollisions() 迭代 objects.indices 途中，結算會呼叫 endGame()
     清空 objects，導致後續索引越界。
     從 crash report 的 backtrace 確認：
       Array._checkSubscript → GameEngine.resolveCollisions()
     修法：先標記再結算（收集 caught / missed 兩個陣列，迴圈結束後才處理），
     並在 tick 中加 guard phase == .playing 阻止結束後繼續生成。

  2. 頭髮蓋住眼睛 → 調整 FaceView 比例。

  3. 暫停畫面「繼續」按鈕白底白字看不見 → 改用難度主色。

  另外把對手的頭從上下顛倒改回正面（顛倒反而難辨識），蜥蜴符號 🤏 → 🦎
  （判讀速度優先）。

  用 RunCodeSnippet 驗過三拳／五拳的判定、勝負相反的翻轉、亂流的順時針
  換拳，全數正確。

第 4 輪：地獄模式的血量、智慧道具的暴斃問題
================================================================================

【使用者需求】
  困難模式改三顆心，現在智慧一結束或智慧時變拳會導致玩家無法反應直接
  暴斃，改成智慧期間及智慧後一秒內不會變拳，且智慧即將結束時畫面閃爍
  （閃原本該出現的掉落物）

【困難改三顆心】
  lives: 1 → 3，副標題同步改成「五拳 · 3 顆心 · 最快」。

【智慧期間與結束後 1 秒不換拳】
  新增 handSwapFreezeRemaining。智慧生效時每幀重設為 1 秒，倒數整個凍住；
  智慧消失後這 1 秒才開始流逝，流完才解凍。
  關鍵是解凍那一刻會補滿預告時間：
    handSwapRemaining = max(handSwapRemaining, telegraphLead)
  沒有這行的話，如果剛好在「距離換拳只剩 0.5 秒」時吃到智慧，凍結解除後
  還是會立刻換拳 —— 暴斃問題只是延後 1 秒發生。
  凍結期間 isTelegraphing 回傳 false，接盤不會閃預告。

  實際跑引擎驗證：
    無道具 1.5 秒        → 倒數正常前進（8 秒間隔走了 0.186）
    智慧中 2.5 秒        → 進度固定 0.000，無預告
    智慧解除後 0.5 秒    → 仍凍結（緩衝中）
    智慧解除後 1.5 秒    → 恢復倒數
    邊界：在「距離換拳只剩 1.00 秒」時吃智慧 → 智慧期間沒換拳 → 解凍後
          距離換拳 1.67 秒（補到 2 秒後又走了 0.33 秒），拳型全程未變

【智慧即將結束時閃回真實落下物】
  showsWisdomHints 改成時間相依，分三段：
    剩 > 1.8 秒     正常顯示接／躲標記
    1.8 ～ 0.5 秒   每 0.3 秒在「標記」與「真實落下物」之間交替閃爍
    最後 0.5 秒     完全交還判讀，不再顯示標記
  最後那 0.5 秒是額外加的：只有閃爍的話，效果會在某個閃爍格上突然消失，
  玩家等於在閃到一半時被丟回真實畫面。
  閃爍節奏用 Int(remaining / 0.3) % 2 綁在道具倒數上而非畫面時鐘，相位
  固定且一定收在「真實」那一格。

  附帶效果：智慧期間「下次換拳」進度條會停住不動，這本身就是個訊號。

  吸血鬼的外圈，把切線往下挪到 y=948 才乾淨。

【難度設定】
  項目                        值                       依據
  血量/速度/生成/換拳         5 / 250 / 1.15s / 10s    與簡單完全相同
  道具                        有
  遞增                        週期20s ×1.09 / ×0.91    與困難相同
  剋制表                      不顯示                   規格的設計意圖

  關於「難度增加速度等同困難」：遞增參數是 DifficultyConfig 上全難度共用
  的，所以地獄的遞增本來就與困難一模一樣，沒有另外加設定。

  會連帶改到地獄，那時才需要把遞增拆成每個難度各自設定。

【使用者需求】
  新增 app icon 及 app 名稱（猜猜拳）還有得分音效
  （附 1254×1254 圖示稿 PNG 與 1.15 秒的硬幣音效 mp3）

【App 名稱】
  INFOPLIST_KEY_CFBundleDisplayName = 猜猜拳
  建出來的 bundle 確認 CFBundleDisplayName = 猜猜拳。

【App Icon】
  iOS 圖示必須不透明正方形、圓角由系統套用，而原稿帶白邊與圓角，不能直接用。
  寫了 /tmp/icon/makeicon.swift 處理，三步：
    1. 泛洪找出外圍白色 → 取非白內容的 bbox（1114×1111）→ 裁掉白邊，
       讓紙紋鋪滿整個正方形
    2. 剩下圓角那四小塊（占 4%）補成紙色
    3. 輸出 1024×1024 無 alpha

  踩了兩個坑：
    - 第一版用逐格容差泛洪，66% 的像素被誤判成白邊，紙紋整片被壓成單色、
      閃光也被洗淡。原因是容差讓它從白色一路漸變走進紙面。改成嚴格白色
      門檻（≥238）才正常。
    - 補色取樣取到抗鋸齒的混色，rgb(234,215,195) 明顯偏白，角落出現淡斑。
      改成把遮罩往內膨脹 14px 後再取那一圈，得到 rgb(197,149,100) 才對得
      上紙色。另外把填充範圍外擴 4px，吃掉圓角邊緣殘留的抗鋸齒淡線。

  【例外處理】ASSETCATALOG_COMPILER_APPICON_NAME 這個設定 MCP 的 build
  setting 工具不認（回報 unknown build setting，整類 ASSETCATALOG_* 都
  不認），所以這一項是直接改 project.pbxproj —— 雖然工具說明要求不要直接
  改。做法：先備份到 /tmp/pbxproj.backup，以 INFOPLIST_KEY_CFBundleDisplayName
  為錨點在兩個 build configuration 各插一行，改完用 plutil -lint 驗過格式，
  再重建確認 CFBundleIcons.CFBundleIconName = AppIcon、圖示有進 Assets.car。
  若偏好用 Xcode UI 設定這一項，把那兩行刪掉再從 Build Settings 設即可。

【得分音效】
  Game/SoundPlayer.swift，音效檔放在 ioshw1/Resources/score-coin.mp3
  （synchronized group 自動納入 bundle）。接對得分時在 resolveCatch 的
  .playerWins 分支觸發。

  兩個設計選擇：
    - 4 個 player 輪流用。單一 AVAudioPlayer 重播會把前一聲切掉，連續接對
      時聲音會斷得很難聽；預先建 4 個輪替就能疊著響。
    - AVAudioSession 用 .ambient。會與其他 app 的聲音共存，也尊重使用者的
      靜音開關。若希望靜音時也要出聲，改成 .playback。

  驗證：bundle 內找得到檔案、可解碼（1.15 秒 / 2 聲道）、category 確認為
  Ambient、連打 4 次無錯誤。
  音效長度 1.15 秒偏長，連續接對時 4 個聲道會大量重疊可能顯得吵雜；裁到
  0.3～0.5 秒會清脆很多（未動，因為那是使用者的素材）。
  無法聽模擬器的聲音，所以音效是「資源載入 + 播放路徑 + 無錯誤」層級的
  驗證，實際聽感需使用者試玩確認。

已知限制與後續可調整處
================================================================================

1. 天黑請閉眼目前是「全畫面黑 0.9 秒」。對話中曾提出改為「下半個畫面黑掉
   三秒」，該修改未執行。

2. 四個難度共用一組遞增參數（rampPeriod / speedRampFactor /
   spawnRampFactor 是 DifficultyConfig 的計算屬性）。要讓各難度遞增不同，
   需改成每個難度各自儲存。

3. 結算畫面不再滾動，靠壓縮剋制表適應螢幕高度（直徑 130～300）。比
   iPhone SE 更短的顯示環境會裁切而非滾動。

4. 地獄模式沒有真正的絕境拳（最少的蜥蜴仍可接 2 種）。

5. 產生器與原始資料放在 /tmp（重開機會清空）：
     /tmp/hell/matchups.tsv    地獄對戰表原始資料
     /tmp/hell/gen.py          產生 HellRuleSet.swift 的腳本
     /tmp/slice/slice.swift    貼紙表切圖工具
     /tmp/icon/makeicon.swift  App Icon 處理工具
     /tmp/pbxproj.backup       改 pbxproj 前的備份
   HellRuleSet.swift 的檔頭註解指向 /tmp/hell/gen.py，那個路徑會消失。
   若日後要重新產生地獄資料表，建議把 matchups.tsv 與 gen.py 移進專案
   （例如 Tools/）並更新註解。

6. 難度數值尚未經過長時間試玩調校。四個難度的數字集中在
   Models/Difficulty.swift 的 config，遞增參數在同檔 DifficultyConfig 底部。

7. 音效為 1.15 秒，連續得分時會多聲重疊。
